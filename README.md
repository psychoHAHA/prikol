# Draft Lab

Прототип помощника по драфту Dota 2. Приложение предлагает героев против выбранных соперников и показывает статистику покупок на основе данных [STRATZ](https://stratz.com/).

## Что умеет

- Учитывает выбранную позицию, союзников и противников при поиске героев.
- Показывает до пяти рекомендаций и статистику матчапов против выбранных соперников.
- Показывает популярные покупки для героя и позиции, а также примеры покупок в матчах против выбранных соперников, если данных достаточно.

Это статистический ориентир, а не прогноз исхода игры. Матчапы охватывают все позиции, а частота покупки и процент побед с предметом сами по себе не доказывают его эффективность. Примеры матчей могут включать только одного из выбранных противников.

## Требования

- Node.js `^20.19.0` или `>=22.12.0` и npm.
- Токен STRATZ и доступ к его API. Получить токен можно в настройках аккаунта STRATZ.

## Локальный запуск

Установите зависимости:

```bash
npm install
```

Скопируйте `.env.example` в `.env.local` и укажите в нём токен:

```dotenv
STRATZ_TOKEN=ваш_токен
```

Файл `.env.local` исключён из Git. Не публикуйте токен и не передавайте его другим людям.

Запустите backend в первом терминале:

```bash
npm run server
```

Эта команда собирает сервер и запускает его с настройками из `.env.local`. После изменений в файлах `server` перезапустите команду: автоматической пересборки сервера пока нет.

Во втором терминале запустите frontend:

```bash
npm run dev
```

Откройте адрес, который выведет Vite, обычно `http://127.0.0.1:5173`. Vite перенаправляет запросы `/api` на сервер `http://127.0.0.1:3001`. В PowerShell, если выполнение `npm.ps1` запрещено, используйте `npm.cmd` вместо `npm`.

## Команды

| Команда | Действие |
| --- | --- |
| `npm run dev` | Запустить Vite для разработки frontend. |
| `npm run server` | Собрать и запустить backend с `.env.local`. |
| `npm run typecheck` | Проверить типы frontend и backend. |
| `npm test` | Запустить тесты Vitest. |
| `npm run build` | Собрать frontend в `dist`, backend — в `dist-server`. |
| `npm run check` | Последовательно проверить типы, запустить тесты и собрать проект. |
| `npm start` | Запустить уже собранный backend. |

Для запуска собранного приложения сначала выполните `npm run build`, затем передайте `STRATZ_TOKEN` через окружение и выполните `npm start`. Сервер раздаёт frontend и API с одного адреса. По умолчанию он слушает `127.0.0.1:3001`; переменная `PORT` задаёт порт и включает прослушивание на `0.0.0.0`. `npm start` сам не загружает `.env.local`.

## Как устроен проект

```text
src/
  app/                 точка входа и общие стили
  pages/draft/         страница драфта и её состояние
  features/draft/      расчёт рекомендаций
  shared/api/          клиент серверного API
  shared/types/        общие типы frontend
server/
  index.ts             HTTP-маршруты, проверка параметров, раздача frontend
  stratz-client.ts     GraphQL-запросы к STRATZ и обработка ошибок
  *-service.ts         получение и обработка данных по отдельным задачам
  cache.ts             кэш ответов
  rate-limit.ts        ограничение частоты запросов
  errors.ts            тип серверной ошибки
```

Браузер запрашивает данные у собственного Node.js API; сервер обращается к STRATZ, обрабатывает ответ и возвращает JSON. Расчёт списка рекомендаций находится на frontend в `recommend.ts`.

Основные маршруты: `GET /api/heroes`, `/api/positions`, `/api/heroes/:id/matchups`, `/api/heroes/:id/items` и `/api/heroes/:id/guide`. Для предметов и гайда параметр `position` принимает значения `POSITION_1`–`POSITION_5`; для гайда `against` содержит до пяти ID противников через запятую.

## Текущие ограничения

- Кэш хранится 15 минут в памяти процесса; ограничитель запросов тоже хранится в памяти. При перезапуске они очищаются и не разделяются между экземплярами сервера.
- Типы описывают ожидаемые ответы STRATZ, но не заменяют полную проверку всех внешних данных во время выполнения.
- Подбор учитывает минимальную выборку и статистику позиции; текущая формула не учитывает синергию союзников и не предсказывает результат конкретного матча.
- План дальнейшего развития находится в [plan.md](plan.md).
